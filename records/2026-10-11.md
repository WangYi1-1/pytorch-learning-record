## 一、复习：历史到底记录什么

当前玩具任务的指令是“先到某种颜色，再到另一种颜色”。

历史记录的是按顺序已经完成的子任务，不是所有选过的图片，也不是任意长度的真实移动轨迹：

```text
[]：还没有完成第一个目标
["red"]：已经完成红色目标
```

第46课通过预设几种历史，使用规则演示当前目标和 STOP。它不训练神经网络，也没有让行动结果自动生成下一次历史的完整反馈循环。

第47课让模型学习给定指令、图片和历史时的当前候选选择。

## 二、第47课：为什么第0、1条样本可以是同一句指令

Dataset 先生成一个场景的指令、候选顺序和图片，然后连续添加两条状态不同的样本。

例如候选顺序为：

```text
位置：0     1    2      3
颜色：blue  red  green  yellow

样本0：指令“先红后绿”，同一组图片，空历史，正确候选位置=1
样本1：指令“先红后绿”，同一组图片，已完成红色，正确候选位置=2
```

所以：

- 样本编号不同，不代表指令文字一定不同；
- 第0、1条共用一个场景，第2、3条共用下一个场景；
- 历史不同，当前正确候选也不同；
- 正确标签是候选位置，不是固定颜色编号。

历史编号另有约定：

```text
0：空历史
1：已完成red
2：已完成green
3：已完成blue
4：已完成yellow
```

不能把样本编号、颜色编号、历史编号、候选位置混成同一种编号。

## 三、模型：先融合文字与历史，再加入图片

模型不是先把图文融合成指令，再加历史。实际顺序是：

```text
指令 → 冻结BERT → CLS特征 [B, 128] → 文本投影 [B, 16]
历史编号 [B] → 可训练Embedding → 历史特征 [B, 16]

文本与历史拼接 [B, 32]
→ 上下文融合模块
→ 上下文特征 [B, 16]
```

projection 的中文是“投影”，这里是可训练的特征投影层。维度不变的 Linear 也会改变特征数值，并不是无作用。

图像分支：

```text
候选图片 [B, 4, 3, 16, 16]
→ 合并样本与候选维度 [B×4, 3, 16, 16]
→ CNN、全局平均池化、展平、图像投影 [B×4, 16]
→ 恢复候选分组 [B, 4, 16]
```

随后：

```text
上下文 [B, 16] → unsqueeze、expand → [B, 4, 16]
上下文与图片逐元素相乘 → 交互特征 [B, 4, 16]

上下文 + 图像 + 交互，沿最后一维拼接
→ [B, 4, 48]
→ 候选打分器 Linear(48,32) → ReLU → Linear(32,1)
→ [B, 4, 1]
→ squeeze(-1)
→ 候选分数 [B, 4]
```

这里的“+”表示拼接，不是数值相加。输出的是分数，不是概率；argmax 才把分数转换成候选位置编号。

BERT 冻结后仍参与前向传播，但不更新参数。文本投影、CNN、历史 Embedding、融合模块和打分器仍可训练。历史编号0是有效状态，查到的空历史向量可以训练，不等于全零向量。

## 四、两个不同的历史对照，不再混淆

### 1. 整体清空历史的评估

```python
evaluate(..., use_history=False)
```

内部执行：

```python
history_ids = torch.zeros_like(history_ids)
```

它把所有历史编号替换成0，用同一个训练好的模型比较正常历史与统一空历史时的整体准确率。

历史分支没有删除，也没有重新训练；所有样本都查历史 Embedding 的第0行。

### 2. 配对样本的预测展示

```python
pair = test_dataset.samples[:2]
batch = collate_batch([test_dataset[0], test_dataset[1]])
encoded, images, history_ids, _ = batch
```

理解变化：

- pair 直接取前两条样本字典，供打印原始信息；
- test_dataset[0] 会调用 __getitem__(0)，返回模型需要的四个字段；
- collate_batch 把两条样本整理成一批输入；
- 拆出 history_ids 是读取历史字段，不是删除或清空历史；
- _ 接住暂时不用的正确标签；
- 两条样本的历史早就在 Dataset 中构造好了，这段不现场修改历史。

更准确的注释是：

```python
# 配对预测展示：取同一场景中两条现成样本，指令和图片相同、历史不同。
# 这里不修改历史；观察模型是否按历史状态切换目标（正确标签也不同）。
```

这段观察模型能否在空历史时选第一个目标、第一步已完成时选第二个目标。它不是新增的“去除历史分支”实验，也不是第一条预测后自动更新第二条的历史。

## 五、训练与保存的复习

```python
optimizer.zero_grad()  # 清空旧梯度，不清空权重
loss.backward()       # 根据当前批次损失计算梯度
optimizer.step()      # 根据梯度更新权重和偏置
```

PyTorch 默认累加梯度，因此通常每批反向传播前先清空旧梯度。梯度来自当前计算图，不是与上一批结果做差求导。

```python
torch.save(model.state_dict(), model_path)
```

保存的是模型状态字典，包含各层参数及持久化状态，不包含模型类和 forward 代码。冻结的 BERT 参数也会保存。以后先创建相同结构，再加载状态。

这一句本身不判断模型是否最优；外面的验证指标比较决定何时保存。这里保存的是模型状态，不是完整的优化器与训练进度。

评估时也复习了：

- scores.argmax(1) 得到每条样本的预测候选编号；
- 与 labels 比较，再 sum，统计预测正确数；
- 默认交叉熵是批次平均损失，乘实际 batch_size 后累加，再除总样本数；
- model.eval() 切换评估模式，torch.no_grad() 关闭梯度记录；
- Tokenizer 的 BatchEncoding 支持整体 .to(device)，普通字典没有这个方法。

## 六、第48课开头：模型是玩家，环境是关卡与进度管理

第47课的第二条样本带着预先写好的“第一步已完成”历史，不受第一条预测是否正确影响。

第48课则从空历史开始，只有执行结果真的完成当前目标，才推进历史。第一步选错，不会自动获得正确的第二步历史。

```python
self.subtasks = ["red", "green"]  # 任务要求：先红后绿
self.completed_subtasks = []     # 实际完成进度：从空开始
```

当前理解：

- 模型负责根据指令、图片和历史选择候选；
- 环境保存场景和任务要求，接收选择、检查完成情况、维护进度；
- 两步完成后停止，未完成但达到步数上限也要退出，不能报成功；
- 环境是普通 Python 类，不是另一套神经网络，更不是 Python 安装环境；
- 本课把“到达一个区域”简化为“选中一张颜色图片”，没有模拟三维移动。

为简化玩具环境，任务目标顺序由正确标签取得，只用于环境检查，不直接传给模型。完成验证与 STOP 由已知规则决定，尚不是学出来的验证器或停止动作。
