今天的主线是：

## 一、训练顺序敏感的 Transformer

`test40_train_transformer_classifier.py` 使用自动生成的两步动作指令，对比了两种模型：

- Embedding 后直接平均池化；
- 加入位置向量并经过 Transformer Encoder。

例如：

```text
turn left then right
turn right then left
```

两句话使用相同的词，但第一个动作不同。平均池化只统计有哪些 token，不能可靠区分顺序；Transformer 结合位置向量后可以根据顺序进行分类。

实验结果：

```text
平均池化模型：约50%
Transformer模型：100%
```

这次实验把以前学过的“位置编码能够表示词序”落实成了真正的训练对比。

## 二、训练集、验证集、测试集与最佳模型

`test41_transformer_generalization.py` 将完整训练流程拆成：

```text
训练集：更新模型参数
验证集：选择训练过程中表现最好的模型
测试集：最后只使用一次，评价最终模型
```

保存最佳模型时，不再只比较准确率。当验证准确率相同，还会选择验证损失更低的模型：

```python
is_better_model = (
    validation_accuracy > best_validation_accuracy
    or (
        validation_accuracy == best_validation_accuracy
        and validation_loss < best_validation_loss
    )
)
```

这样可以避免多个模型准确率相同，却错误地保留置信程度较差的模型。

## 三、第一次使用预训练 BERT

`test42_pretrained_bert.py` 使用小型预训练 BERT：

```text
google/bert_uncased_L-2_H-128_A-2
```

Tokenizer 负责完成：

```text
原始文字
→ 分词
→ token ID
→ 添加 [CLS] 和 [SEP]
→ padding
→ attention_mask
```

模型前向传播：

```text
input_ids [batch, sequence]
→ BERT
→ last_hidden_state [batch, sequence, 128]
```

下面的代码取得每条指令第0个位置的 `[CLS]` 特征：

```python
cls_features = outputs.last_hidden_state[:, 0, :]
```

形状为：

```text
[batch, 128]
```

`[CLS]` 在自注意力过程中融合整句话的信息，因此常被当作句子级特征交给分类头。

## 四、冻结 BERT 并训练动作分类头

`test43_frozen_bert_classifier.py` 的模型结构是：

```text
文字指令
→ 预训练Tokenizer
→ 冻结的BERT编码器
→ [CLS]句子特征 [batch, 128]
→ Linear(128, 4)
→ 四类动作logits
```

冻结 BERT：

```python
for parameter in self.text_encoder.parameters():
    parameter.requires_grad = False
```

这样反向传播时只训练新建的分类头，不修改 BERT 已经学到的参数。本次可训练参数只有516个，而冻结的 BERT 参数约438万个。

小型指令测试集达到100%，说明“预训练文本特征 + 新任务分类头”的代码链路已经跑通；但样本量很小，不能把这个结果理解成真实场景下也能达到100%。

## 五、图文双分支模型

`test44_multimodal_fusion.py` 首次把文字和图片放入同一个模型。

文本分支：

```text
指令 → BERT → CLS特征 [batch, 128]
→ Linear投影 → [batch, 16]
```

图像分支：

```text
候选图片 [batch, candidate, 3, 16, 16]
→ 临时合并batch与candidate
→ CNN
→ 每张图片的16维特征
→ 恢复为 [batch, candidate, 16]
```

为了给每张候选图片都配上同一条文字指令，文字特征经过：

```text
[batch, 16]
→ unsqueeze
[batch, 1, 16]
→ expand
[batch, candidate, 16]
```

然后将文字特征与每张候选图片的特征融合，输出：

```text
candidate_scores [batch, candidate]
```

每个分数表示对应候选图片与当前文字指令的匹配程度，`argmax(dim=1)` 选择得分最高的候选位置。

## 六、训练图文融合候选打分模型

`test45_train_multimodal_fusion.py` 自动生成简化的颜色导航任务：

```text
指令：move toward the red area
候选：[blue, yellow, green, red]
正确标签：3
```

候选图片不是完全固定的纯色块，而是加入随机亮度与噪声：

```text
颜色RGB
→ 扩展为 [3, 16, 16]
→ 随机亮度
→ 随机噪声
→ clamp到 [0, 1]
```

四张候选图片会被随机打乱，再用 `torch.stack()` 合成：

```text
4 × [3, 16, 16]
→ [4, 3, 16, 16]
```

这样模型必须根据文字和图片内容选择答案，不能记住某种颜色总在固定位置。

## 七、一次重要的失败实验与修正

最初只拼接文字特征和图像特征：

```text
[text, image]
```

模型没有稳定学会两种模态之间的匹配，准确率停留在四选一随机水平附近。随后显式增加逐元素乘法产生的交互特征：

```python
interaction_features = (
    expanded_text_features * image_features
)

fused_features = torch.cat(
    [
        expanded_text_features,
        image_features,
        interaction_features
    ],
    dim=-1
)
```

形状变化：

```text
16维文字 + 16维图像 + 16维交互
→ 48维融合特征
```

加入交互后，训练集很快达到100%。但是当验证集和测试集改用训练阶段完全没有出现过的新句式时，准确率仍只有25%。这说明模型记住了训练句式与颜色的组合，没有学会可靠的陌生句式泛化。

为了先单独验证图文融合流程，最终让训练、验证和测试使用相同的句式集合，但使用不同随机种子生成不同的图片噪声和候选顺序。结果为：

```text
第1轮验证准确率：50%
第5轮验证准确率：100%
最终测试准确率：100%
```

这个结果只能证明模型学会了当前受控范围内的“文字颜色与图片颜色匹配”，不能证明它已经能处理任意自然语言表达或真实导航图片。

## 八、今天形成的整体认识

CNN、Transformer、BERT 和图文融合模型虽然处理的数据不同，但训练框架仍然一致：

```text
Dataset生成样本
→ DataLoader组成batch
→ 模型前向传播
→ CrossEntropyLoss比较候选分数和正确位置
→ backward计算梯度
→ optimizer更新可训练参数
→ 验证集选择最佳模型
→ 测试集评价并打印预测
```

新的核心认识是：

1. BERT负责将文字变成句子特征，CNN负责将图片变成图像特征；
2. 图文融合不是简单地把两个向量放在一起，还要让模型有机会学习二者的对应关系；
3. 训练集100%不代表模型真正理解任务，验证集使用陌生句式时的25%揭示了过拟合；
4. 简化合成实验适合验证代码链路，但后续必须逐步增加语言、图像和导航任务的真实性。
