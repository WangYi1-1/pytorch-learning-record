记录日期：2026-09-21。

今天完成了从“文本预处理”到“真正训练文本模型”的跨越，并将以前用 NumPy 手写的 Transformer 原理迁移到 PyTorch 官方组件。

今天的两条主线：

```text
文本分类：

→ 掩码平均池化 → 分类头 → 训练动作分类器
```

## 一、自定义 Dataset

`test38_train_text_classifier.py` 中创建了 `InstructionDataset`，每条数据包含：

```text
(文字指令, 正确动作编号)
```

例如：

```python
("turn left", 1)
```

`__len__()` 返回数据集样本数，`__getitem__()` 根据下标返回一条处理好的数据。

```python
def __getitem__(self, index):
    instruction, label = self.samples[index]
```

文字经过分词和词表查找后变成 token ID Tensor，未见词使用 `<unk>` 的编号。

## 二、collate_fn 与动态 Padding

不同指令的 token 数量不同，DataLoader 的默认整理方法无法直接将它们组成规则 Tensor。

```python
collate_fn=collate_batch
```

这句代码指定：当 DataLoader 取出一批数据后，使用自定义的 `collate_batch()` 完成组装。

`collate_batch()` 的工作：

1. 用 `zip(*batch)` 将 token 序列和标签分开；
2. 找到当前 batch 中的最长序列；
3. 创建填满 `pad_id` 的 `input_ids`；
4. 将真实 token 写入每一行的前面；
5. 生成 `attention_mask`；
6. 用 `torch.stack(labels)` 将多个标量 Tensor 组成 `[batch_size]`。

`torch.stack()` 会新建一个维度。例如：

```text
4个标量Tensor
→ stack
→ labels形状 [4]
```

## 三、真正可训练的文本动作分类器

`TextActionClassifier` 的结构：

```text
input_ids
[batch, sequence]

→ Embedding
[batch, sequence, 16]

→ 掩码平均池化
[batch, 16]

→ Linear(16, 16) + ReLU + Linear(16, 4)
[batch, 4]
```

Embedding 内部的参数表形状是：

```text
[vocabulary_size, embedding_dim]
```

`embedding_dim=16` 表示每个 token 使用16个可训练特征表示。这不是在原来4个特征后再加一维，而是本次直接选择16维词向量。

参数更新时，不仅分类头发生变化，Embedding 中各 token 的向量也会通过反向传播学习。

## 四、训练流程与 CNN 的联系

文本模型与之前 CNN 的整体训练框架完全相同：

```text
DataLoader分批
→ 前向传播
→ 计算交叉熵损失
→ 梯度清零
→ 反向传播
→ 优化器更新参数
→ 评估新数据
```

区别在于特征提取方法：

```text
CNN：
图片 → 卷积层提取图像特征 → 分类头

文本模型：
token ID → Embedding提取文本特征 → 分类头
```

所以之前掌握的 loss、backward、optimizer、train/eval 和 DataLoader 都能直接复用，只需要替换数据处理和模型结构。

## 五、文本分类器的实际运行结果

微型数据集包含32条训练指令，四类动作：

```text
move forward
turn left
turn right
stop
```

训练100轮后，训练集准确率达到100%。未原样出现在训练集中的四条测试指令也全部预测正确：

```text
head straight → move forward
take a left   → turn left
make a right  → turn right
remain here   → stop
```

这证明代码链路已经跑通，但数据集很小，不能因此100%准确率就认为模型已具备广泛的语言理解能力。

## 六、普通平均池化的限制

`test38` 的句子特征来自 token 向量的平均。因为加法不区分顺序，下面两句话会得到完全相同的平均向量：

```text
turn left then right
turn right then left
```

两者包含相同的 token，只是顺序不同。普通平均池化更接近“词袋”，不能真正理解词序。

## 八、PyTorch Transformer Encoder Layer

```python
encoder_layer = nn.TransformerEncoderLayer(
    d_model=16,
    nhead=4,
    dim_feedforward=32,
    dropout=0.0,
    batch_first=True
)
```

参数含义：

| 参数 | 含义 |
|---|---|
| `d_model=16` | 每个 token 的特征维度是16 |
| `nhead=4` | 使用4个注意力头，每个头的维度为4 |
| `dim_feedforward=32` | FFN 内部按 `16 → 32 → 16` 变换 |
| `dropout=0.0` | 当前为了稳定观察而关闭 Dropout |
| `batch_first=True` | 输入排列为 `[batch, sequence, feature]` |

一个 `TransformerEncoderLayer` 内部包含：

```text
多头自注意力
→ 残差连接与LayerNorm
→ FFN
→ 残差连接与LayerNorm
```

## 九、TransformerEncoder 层叠加

```python
self.encoder = nn.TransformerEncoder(
    encoder_layer=encoder_layer,
    num_layers=1,
    enable_nested_tensor=False
)
```

- `encoder_layer`：指定每一层的结构模板；
- `num_layers=1`：当前只叠加一层；
- `enable_nested_tensor=False`：不启用针对大量 padding 的 Nested Tensor 优化，保持普通三维 Tensor，便于学习形状。

层数改变时，特征数值继续被加工，但形状保持：

```text
[batch, sequence, 16]
→ Encoder Layer 1
→ [batch, sequence, 16]
```

## 十、Transformer 前向传播的完整形状

`test39` 的前向传播：

```text
input_ids
[2, 4]

→ Token Embedding
token_features
[2, 4, 16]

→ Position Embedding
position_features
[2, 4, 16]

→ token特征 + 位置特征
features
[2, 4, 16]

→ Transformer Encoder
encoded_tokens
[2, 4, 16]

→ 掩码平均池化
sentence_features
[2, 16]

→ Linear分类头
logits
[2, 4]
```

PyTorch 的 `src_key_padding_mask` 与之前自定义 `attention_mask` 含义相反：

```text
attention_mask：1=真token，0=padding
padding_mask： False=真token，True=padding
```

因此需要：

```python
padding_mask = attention_mask == 0
```

## 十一、位置信息实验

`test39` 使用两条 token 完全相同、只是顺序不同的指令进行对比。

运行结果：

```text
普通平均池化后的两个向量是否相同：
True

加入位置信息并经过Transformer后，两个句子向量是否相同：
False
```

实验说明：

> Embedding 的普通平均只知道句子里有哪些词；位置特征和 Transformer 让模型有能力区分这些词以什么顺序出现。

当前 `test39` 只验证前向传播和形状，还没有训练，因此最后的 logits 还不是有意义的动作预测。
