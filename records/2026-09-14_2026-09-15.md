## 二、Tensor：先区分数值、形状和含义

Tensor 是 PyTorch 用来存放和计算数值的数据结构。

```python
torch.tensor(2.0)       # 标量，形状 []
torch.tensor([2.0])     # 一维，形状 [1]
torch.tensor([[2.0]])   # 二维，形状 [1, 1]
```

这三种写法都只有一个元素，但维度不同。

一个关键疑惑是：weight 为什么“形状是 [1, 1]，训练结果却是 2”？

答案是：

- `[1, 1]` 是形状，表示一行一列。
- `2.0` 是其中唯一的数值。
- 完整结果是 `tensor([[2.0]])`，并没有变成一维张量。

其他收获：

- `.shape` 查看形状，`.dtype` 查看数值类型，`.device` 查看所在设备。
- `.item()` 只能用于一个元素的张量；与张量有几维无关。
- 多元素张量直接打印，或用 `.tolist()` 转成 Python 列表。
- `torch.tensor([[-3.0], [-1.0]])` 是合法的嵌套列表。
- `torch.tensor([-3.0], [-1.0])` 是传入多个位置参数，不是创建两行数据的正确写法。
- 形状本身不规定数据语义：同样是 `[9]`，作为 Linear 的输入可表示九个特征，作为交叉熵的类别编号目标则表示九条样本的答案。

## 三、Autograd：记录计算与计算梯度不是一回事

自动求导分成两个阶段：

1. 前向计算时记录计算过程，建立计算图。
2. 调用 `loss.backward()`，沿计算图反向求导。

默认开启梯度记录，表示“允许记录”。只有涉及需要梯度的张量等条件满足时，才会建立相应的求导关系；不是所有计算都会自动求导。

```python
x = torch.tensor(3.0, requires_grad=True)
y = x ** 2

y.backward()

print(x.grad)  # tensor(6.)
```

因为 y = x²，其导数是 2x，在 x = 3 处等于 6。

### 用线性模型理解参数梯度

```python
prediction = w * x + b
loss = (prediction - target) ** 2
```

当 x = 3、w = 2、b = 1、target = 10 时：

- prediction = 7。
- loss = 9。
- ∂loss/∂w = 2 × (7 − 10) × 3 = −18。
- ∂loss/∂b = 2 × (7 − 10) = −6。

梯度表示：在当前参数位置，参数微小变化会让损失变化多快。多个参数的偏导数合起来构成参数梯度。

**不是**拿当前批次与上一批次的预测差、损失差或参数变化量来求导。每一批根据自己的损失，在当前参数位置重新计算梯度；上一批只留下更新后的参数。

## 四、手动更新参数与 no_grad

基本更新规则：

```text
新参数 = 旧参数 − 学习率 × 梯度
```

```python
with torch.no_grad():
    w -= learning_rate * w.grad
    b -= learning_rate * b.grad
```

`with` 是 Python 的上下文管理语法。这里临时关闭自动求导记录，退出缩进块后恢复。

`no_grad` 的意思不是“不允许修改数值”，而是“数值照常修改，但不记录这次操作的求导关系”。普通训练不需要把参数更新过程加入模型的计算图。

需要梯度的叶子参数，在梯度记录开启时直接进行这种原地更新，通常会被 PyTorch 阻止。手动更新时使用 `no_grad`；优化器会处理普通参数更新所需的梯度模式。

### 学习率实验中的一个排错收获

曾经把：

```python
b -= learning_rate * b.grad
```

误写成：

```python
b.grad -= learning_rate * b.grad
```

结果只修改了梯度，参数 b 一直保持 3.0，随后梯度又被清零。模型仍然能通过调整 w 接近答案，所以“损失下降”并不证明每行代码都写对了。

学习率过大时，预测可能跨过目标来回振荡；是否还能收敛，需要看振荡幅度有没有缩小。

## 五、nn.Module 与 nn.Parameter

```python
class LinearModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.w = nn.Parameter(torch.tensor(2.0))
        self.b = nn.Parameter(torch.tensor(3.0))

    def forward(self, x):
        return self.w * x + self.b
```

理解要点：

- `nn.Module` 管理模型参数和网络层。
- `__init__` 初始化对象，可先类比 Java 构造函数。
- `self` 类似 Java 的 `this`。
- `super().__init__()` 先初始化父类 Module 的内部管理结构。
- `nn.Parameter` 是特殊 Tensor，默认需要梯度；赋给 Module 的成员时，会被登记成模型参数。
- 普通 Tensor 即使设置 `requires_grad=True`，也不会因此自动登记进 `model.parameters()`。
- `forward` 定义模型怎样计算，实际使用写 `model(x)`。
- `model.parameters()` 让优化器取到所有登记的参数。
- 模型的设备移动、参数保存等功能，也依赖这些管理机制。

注意三个 Python 概念不同：

- 类中的 `__init__()`：初始化对象。
- `if __name__ == "__main__":`：区分文件直接运行与被导入。
- 包中的 `__init__.py`：包相关的初始化文件。

## 六、Loss 和 Optimizer：封装手写训练步骤

```python
loss_fn = nn.MSELoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.01)
```

`nn.MSELoss` 是类，`nn.MSELoss()` 创建损失函数对象，`loss_fn(prediction, target)` 调用它。

不能把计算写成 `nn.MSELoss(prediction, target)`，那是在给构造函数传参数。

也可以使用：

```python
nn.MSELoss()(prediction, target)
```

或函数式接口，但把对象在循环外创建一次，更便于复用和阅读。

标准训练步骤：

```python
prediction = model(inputs)
loss = loss_fn(prediction, targets)

optimizer.zero_grad()
loss.backward()
optimizer.step()
```

三者必须分清：

| 操作 | 作用 |
|---|---|
| `zero_grad()` | 清空旧梯度，不清空模型参数 |
| `backward()` | 计算当前损失对参数的梯度，不更新参数 |
| `step()` | 根据梯度更新权重和偏置，不是更新梯度 |

MSE 用于这里的回归练习：先计算各预测误差的平方，再默认取平均。

## 七、nn.Linear：构造顺序与权重形状顺序相反

```python
nn.Linear(in_features=1, out_features=4)
```

必须区分：

```text
创建网络层：Linear(输入特征数, 输出特征数)
weight形状：[输出特征数, 输入特征数]
bias形状：[输出特征数]
```

| 定义 | weight形状 | 含义 |
|---|---|---|
| Linear(1, 1) | [1, 1] | 一个输入，一个输出 |
| Linear(2, 1) | [1, 2] | 两个输入，加权组合成一个输出 |
| Linear(1, 4) | [4, 1] | 一个输入，分别产生四个隐藏特征 |
| Linear(4, 1) | [1, 4] | 四个隐藏特征，加权组合成一个输出 |

每个输出神经元有一个偏置，不是每个权重都有一个偏置。

批次里的样本数不影响 weight 的形状。例如输入 `[9, 1]`，经过 Linear(1, 4) 后变成 `[9, 4]`。

为了避免写反，暂时使用 `in_features=` 和 `out_features=` 的具名写法。

## 八、Dataset 和 DataLoader：图片与答案一直是两份内容

Dataset 提供完整样本：

```python
image, label = dataset[index]
```

正确标签不藏在图片张量里：

- image 是图片张量。
- label 是独立的类别编号。

DataLoader 从 Dataset 取出多条完整样本，将图片和标签分别组合成批：

```python
batch_images, batch_labels = next(iter(dataloader))
```

理解这句时，可以拆成：

```python
data_iterator = iter(dataloader)
first_batch = next(data_iterator)
batch_images, batch_labels = first_batch
```

- `iter` 创建迭代器。
- `next` 取出下一批。
- 左边按位置拆包，第一份是图片，第二份是标签。
- 使用同一个迭代器连续调用 next，才是连续往后取批次。
- for 循环自动管理这样的迭代过程。

`enumerate(dataloader, start=1)` 再给每批添加编号。左侧变量按返回数据的位置接收，不是根据变量名与 start 对应。

### 为什么打乱？

`shuffle=True` 打乱完整样本顺序，不会把图片和正确标签分别打乱。它能减少训练顺序造成的偏向，使普通随机小批量训练的数据顺序更合理。

不是所有顺序都能打乱：时间序列、单条导航轨迹内部等有顺序意义的数据，要按任务设计处理。

## 九、从线性模型到 ReLU 和 MLP

只堆叠线性层，整体仍然是一个仿射变换。例如：

```text
h = 2x + 1
y = 3h + 4 = 6x + 7
```

ReLU 引入非线性：

```text
ReLU(x) = max(0, x)
负数变0，正数保持原值
```

学习的 MLP 结构：

```text
输入 → Linear(1, 4) → ReLU → Linear(4, 1) → 预测
```

第一层产生四个隐藏特征，经过 ReLU 后，第二层对它们加权求和再加偏置。两层都有需要学习的参数，ReLU 没有。

### 平方函数练习的收获

让模型通过训练数据近似 y = x²，而不是把平方公式写进 forward。

曾观察到 x = 0 时预测约 −0.2484。模型是在用有限的结构和训练过程近似函数，不是在执行数学平方运算，所以已见样本也不保证精确拟合，输出也不自动保证非负。

要区分“网络表达能力、训练是否充分、数据覆盖范围”和“代码是否报错”。

## 十、分类：类别分数与正确类别编号

回归预测连续数值；分类从候选类别中选择一个。

玩具动作分类约定：

```text
0：前进
1：左转
2：右转
```

标签编号只是代号，不代表类别之间的大小关系。

```python
logits = model(inputs)       # [9, 3]
targets = torch.tensor(
    [1, 1, 1, 0, 0, 0, 2, 2, 2],
    dtype=torch.long
)                            # [9]
```

- logits 每行提供三个候选类别的分数。
- targets 每个位置给出对应样本的一个正确类别编号。
- logits 是原始分数，可以为负，不要求加起来等于1。
- `argmax(dim=1)` 在每行选出最高分所在的列编号。
- Softmax 不改变最大分数对应的类别，所以选择类别时可以直接对 logits 使用 argmax。

已观察到的玩具分类结果：

```text
输入 −1.25 → 左转
输入  0.00 → 前进
输入  1.25 → 右转
预测编号：[1, 0, 2]
```

这是练习结果，不代表真实导航能力。其中 0.0 参与过训练，不能把这三条全部当作独立的陌生测试样本。

## 十一、交叉熵怎样处理不同的形状？

当前图片分类：

```text
logits：[32, 10]
labels：[32]
```

不是两个张量逐项相减，也不是每张图片有十个正确答案。

对第 i 张图片：

1. logits 的第 i 行提供十个类别分数。
2. labels[i] 告诉损失函数哪一个类别编号正确。
3. 交叉熵可以理解为根据所有分数计算类别概率，取出正确类别的概率。
4. 该样本的损失是 −ln(正确类别概率)。
5. 默认把32条样本的损失取平均。

例如正确标签是9：

```text
正确类别概率80% → 损失约0.223
正确类别概率 2% → 损失约3.912
```

数字9用于定位正确列，不是拿模型分数和9做减法。正确类别概率由全部十个分数共同决定。

实际继续直接使用：

```python
loss_fn = nn.CrossEntropyLoss()
loss = loss_fn(logits, labels)
```

不要先手动 Softmax。函数内部完成数值稳定的等价计算。目前需要理解其语义，不必立刻手推完整导数。

## 十二、准确率与数据划分

```python
predicted_classes = logits.argmax(dim=1)
correct_count = (predicted_classes == targets).sum().item()
accuracy = correct_count / len(targets)
```

这次比较的是两个形状相同的类别编号列表。

- 准确率看最终类别是否选对。
- Loss 还能反映正确类别的相对置信程度。
- 用 Loss 求梯度，用准确率观察分类效果。
- 训练集学习参数，验证集用于选择设置或模型，测试集最终评价。
- 验证和测试不执行参数更新。
- `model.eval()` 不会自动关闭梯度记录，通常与 `torch.no_grad()` 配合。

## 十四、Flatten 与图片 MLP

`nn.Flatten()` 等价于默认范围 `start_dim=1, end_dim=-1`：保留第0维，把第1维到最后一维合并。

```text
[32, 1, 28, 28] → [32, 784]
```

合并的是通道、高、宽三维；因为通道数是1，才看起来像只合并最后两个28。

它不改变像素值，不学习特征，只把每张图片的像素排成一行，适配 Linear 的输入特征维度。

当前图片模型：

```text
输入图片             [32, 1, 28, 28]
Flatten              [32, 784]
Linear(784, 128)      [32, 128]
ReLU                 [32, 128]
Linear(128, 10)       [32, 10]
```

- 784来自像素数。
- 128是人为选择的隐藏特征数量。
- 10来自类别数。
- 模型内部已有 Flatten，直接传原始 batch_images。
- 最后一层输出原始 logits，不再加 ReLU 或手动 Softmax。
- 后续学 CNN 时，会先保留图片的空间结构，而不是先展开。

## 十五、把训练主线彻底串起来

```python
# 模型和当前批次的数据放在同一设备
batch_images = batch_images.to(device)
batch_labels = batch_labels.to(device)

# 当前批次前向计算
logits = model(batch_images)

# 用正确类别计算当前批次的平均损失
loss = loss_fn(logits, batch_labels)

# 清旧梯度、算新梯度、更新参数
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

完整含义：

1. Dataset 提供图片与答案，DataLoader 分别打包。
2. 模型只看图片，计算十个候选类别分数。
3. Loss 根据独立标签判断正确类别，衡量当前预测有多差。
4. backward 利用当前计算图的链式法则，算出两层参数的梯度。
5. step 根据梯度更新两层权重和偏置。
6. 下一批使用更新后的参数继续训练，不重新初始化模型。
7. 图片和标签本身不会因此被训练成新数值。

批次与轮次要分清：

- 每批进行一次反向传播和参数更新。
- 一轮 epoch 是把整个训练集的全部批次处理完。
- 6万张训练图片、batch_size=32时，一轮1875批。
- 当前代码训练3轮，计划进行5625次参数更新。
- 模型只在循环外创建一次；zero_grad不会抹掉已经学习的参数。

GPU 只是加速计算。模型应先移动到设备，再创建优化器；每批图片和标签也要移动到相同设备。

## 十六、排错记录

| 问题 | 原因与修正 |
|---|---|
| `MLP has no attribute layer` | 定义的是 layer1，forward 却写成 layer；名称要一致 |

| `loss.backgrad()` | 方法名笔误，应为 backward |
| b 一直不变 | 更新成了 b.grad，而不是 b |
| 多元素张量不能 item | item只提取单个元素；用索引后item或tolist |
